## Engineering approach

Technology decisions should support the business.

An IT roadmap should not be built in isolation by IT.

We start from the objectives, constraints and operational problems of each business area and identify where technology can accelerate results, reduce operational risk or eliminate unnecessary complexity.

Our approach is based on:

**Understand → Design → Automate → Operate → Improve**

## Engineering principles

### Keep it understandable

Complexity should have a reason.

### Automate repetitive work

If a process is repeated often enough, it should probably be automated.

### Infrastructure is code

Infrastructure should be versioned, reproducible and reviewable.

### Documentation is part of the system

If the infrastructure only works because one person remembers how it works, the infrastructure is incomplete.

### Observe before optimizing

Measure the system before changing it.

### Design for failure

Systems should assume that components will eventually fail.

### Technology follows the business

Technology exists to support business objectives, not the other way around.
